## b) rever-C. Reverse engineer the packd binary to C language with Ghidra. Find the main program. Give variables descriptive names. Explain the program's operation. Solve the task from the binary, without the original source code. ezbin-challenges.zip

Avasin packd binäärin Ghidrassa ja annoin ohjelman analysoida tiedoston. Etsin main funktion Symbol Tree näkymästä ja tarkastelin sitä Decompiler ikkunassa.

Ghidra oli nimennyt muuttujat aluksi automaattisesti. Nimesin ne kuvaavammiksi:

    local_28 -> password
    iVar1 -> password_check

Decompilerista selvisi, että käyttäjän syötettä verrattiin strcmp() -funktiolla merkkijonoon:

    piilos-AnAnAs

Ohjelman ehto oli:

    password_check == 0

Koska strcmp() palauttaa arvon 0, kun merkkijonot ovat samat, päättelin oikeaksi salasanaksi piilos-AnAnAs.

Testasin salasanan ajamalla binäärin:

    ./packd

Ohjelma hyväksyi salasanan ja tulosti lipun:

    FLAG{Tero-0e3bed0a89d8851da933c64fefad4ff2}

# d) Nora CrackMe:

Tehtävässä tutustuin NoraCodesin CrackMe-haasteisiin. Tarkoituksena oli
selvittää ohjelman vaatima salasana tutkimalla valmiiksi käännettyä binääriä
ilman lähdekoodin katsomista.

Nora Tindallin reverse engineering ohjeessa CrackMe määritellään
suoritettavaksi ohjelmaksi, joka tarkistaa käyttäjän antaman syötteen.
Tehtävänä on selvittää oikea syöte tutkimalla binääriä ilman lähdekoodia.

Latasin crackmes repositorion GitHubista:

    git clone https://github.com/NoraCodes/crackmes.git

Tämän jälkeen siirryin kansioon:

    cd ~/crackmes

Katsoin projektin Makefile-tiedoston:

    cat Makefile    

Makefilessä näkyi muun muassa:

    # Compiler: GCC
    CC := gcc
    
    # Common GCC flags
    CCFLAGS := -O1 -fno-stack-protector -lcrypt
    
    # Compiler flags for x86_64
    CCFLAGS64 := $(CCFLAGS) -m64
    
    # Build 64 bit binaries
    %.64: %.c
            $(CC) $(CCFLAGS64) $< -o $@
            objcopy -g $@

Tästä pystyi näkemään, että ohjelmat käännetään GCC:llä 64-bittisiksi binääreiksi.

crackme01:n kääntäminen

Yritin kääntää ensimmäisen CrackMe-ohjelman komennolla:

    make crackme01

Käännös ei aluksi onnistunut, vaan linker antoi virheen:

    cannot find -lcrypt: No such file or directory

Makefilen -lcrypt-asetus tarkoittaa, että käännöksessä tarvitaan crypt-kirjasto.
Asensin puuttuvan kehityspaketin:

    sudo apt install libcrypt-dev

sudo apt install asentaa paketin järjestelmään ja libcrypt-dev sisältää kääntämisessä tarvittavat crypt-kirjaston kehitystiedostot.
Tämän jälkeen kokeilin käännöstä uudelleen:

    make crackme01

Nyt käännös onnistui:

    gcc -O1 -fno-stack-protector -lcrypt -m64 crackme01.c -o crackme01.64
    objcopy -g crackme01.64

Hakemistoon syntyi tiedosto:

    crackme01.64

Binäärin tarkistaminen
Tarkistin, että binääri oli syntynyt:

    ls -la crackme01.64

Tuloksena näkyi:

    -rwxrwxr-x 1 kali kali 15912 Sep 29 12:57 crackme01.64

Tämän jälkeen tarkistin binäärin tyypin:

    file crackme01.64

Tuloksena oli:

    crackme01.64: ELF 64-bit LSB pie executable, x86-64,
    dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2,
    for GNU/Linux 3.2.0, not stripped

file komennolla selvisi, että kyseessä oli 64-bittinen x86-64 ELF-binääri.

Tulosteessa näkyi myös:

    not stripped

Seuraavaksi tarkoituksena oli ratkaista crackme01 tutkimalla binääriä ilman lähdekoodin katsomista.
strings-komennon käyttö
Aloitin tutkimalla binäärissä olevia merkkijonoja:

    strings ./crackme01.64

strings etsii binääritiedostosta tulostettavia merkkijonoja.
Tulosteessa näkyi muun muassa:

    Need exactly one argument.
    password1
    No, %s is not correct.
    Yes, %s is correct!

Merkkijono:

    password1

vaikutti mahdolliselta ohjelman hyväksymältä salasanalle.
Salasanan testaaminen
Testasin löydettyä merkkijonoa ohjelman argumenttina:

    ./crackme01.64 password1

    Ohjelma vastasi:
    Yes, password1 is correct!
        
crackme01e ratkesi samalla tavalla kuin crackme01. Molemmissa oikea
salasana oli tallennettu binääriin selväkielisenä merkkijonona, joten se
löytyi `strings`-komennolla.

# F) Nora crackme02. Name the main program's variables from the reverse-engineered binary and explain the program's operation. Solve the binary.

Aloitin kääntämällä ohjelman binääriksi komennolla:

bash

    make crackme02

make käyttää projektin Makefile tiedostoa ja kääntää crackme02.c-lähdekoodista 64-bittisen binäärin nimeltä:

    crackme02.64

Seuraavaksi tarkistin binäärin tyypin:

    file crackme02.64

file kertoo tiedoston tyypin ja perustietoja binääristä, kuten onko se ELF-binääri, 64-bittinen ja mille arkkitehtuurille se on käännetty.
Tämän jälkeen tutkin binäärin sisältämiä luettavia merkkijonoja:

    strings ./crackme02.64

Tulosteessa näkyi muun muassa:

    password1
    Need exactly one argument.
    No, %s is not correct.
    Yes, %s is correct!

Kokeilin password1

    ─$ ./crackme02.64 password1
    No, password1 is not correct.
    
Käynnistin ghridra ja aloin tutkimaan tiedostoa ja siirryin "main" funktioon:

    undefined8 main(int param_1,long param_2)
    
    {
      char *pcVar1;
      char cVar2;
      undefined8 uVar3;
      char *pcVar4;
      char *pcVar5;
      
      if (param_1 == 2) {
        pcVar1 = *(char **)(param_2 + 8);
        pcVar5 = "password1";
        cVar2 = 'p';
        pcVar4 = pcVar1;
        do {
          pcVar5 = pcVar5 + 1;
          if (*pcVar4 == '\0') break;
          if (cVar2 + -1 != (int)*pcVar4) {
            printf("No, %s is not correct.\n",pcVar1);
            return 1;
          }
          cVar2 = *pcVar5;
          pcVar4 = pcVar4 + 1;
        } while (cVar2 != '\0');
        printf("Yes, %s is correct!\n",pcVar1);
        uVar3 = 0;
      }
      else {
        puts("Need exactly one argument.");
        uVar3 = 0xffffffff;
      }
      return uVar3;
    }

Ghidran decompiler oli nimennyt muuttujat automaattisesti. Niiden käytön perusteella tulkitsin ne seuraavasti:

    param_1 -> argc
    param_2 -> argv
    pcVar1  -> user_input
    pcVar4  -> input_pointer
    pcVar5  -> password_pointer
    cVar2   -> password_char
    uVar3   -> return_value

Ghidran decompilerissa huomasin kohdan:

    if (cVar2 + -1 != (int)*pcVar4)

En aluksi ymmärtänyt, mitä + -1 tarkoitti tässä yhteydessä, joten käytin tekoälyä vihjeiden saamiseen.
Tekoälyn vihjeen avulla ymmärsin, että:

    cVar2 + -1

on sama asia kuin:

    cVar2 - 1

Tämän jälkeen tarkistin ASCII-taulukosta merkkien arvot itse.

komennolla "man ascii" näkee ASCII arvot

    man ascii
    
Tämän perusteella ymmärsin, että ohjelma ei vertaa käyttäjän syötettä suoraan merkkijonoon "password1", vaan jokaisen merkin ASCII arvosta vähennetään yksi ennen vertailua.

p = 112
112 - 1 = 111
111 = o

Arvojen perusteella tuli = 

    o`rrvnqc0
