# H2 Now we hack! and code

## OWASP : A01 borken Access control

  * Broken Access Control tarkoittaa sitä, että käyttäjä pystyy tekemään
  asioita tai pääsemään tietoihin, joihin hänellä ei pitäisi olla oikeuksia.
  
  * Haavoittuvuus voi esimerkiksi mahdollistaa tavallisen käyttäjän pääsyn
  ylläpitäjälle tarkoitettuihin toimintoihin.
  
  * Käyttäjille pitäisi antaa vain ne oikeudet, joita he tarvitsevat.
  Käyttöoikeuksien toimivuutta pitäisi myös testata.

## Karvinen 2023: Find Hidden Web Directories - Fuzz URLs with ffuf

  * ffuf on web fuzzing -työkalu, jolla voidaan etsiä esimerkiksi
  piilotettuja URL-polkuja ja hakemistoja.

  * ffuf on työkalu, jolla voidaan etsiä verkkosivuilta piilotettuja hakemistoja ja sivuja automaattisesti. Se kokeilee eri      osoitteita sanalistan avulla, joten niitä ei tarvitse käydä läpi käsin. ffufilla voidaan testata myös esimerkiksi HTTP-      headereita ja POST-parametreja.


## PortSwigger: Access control vulnerabilities and privilege escalation

  * Käyttöoikeuksien hallinta määrittää, mitä toimintoja käyttäjä saa tehdä ja mihin tietoihin hän pääsee  käsiksi.Vertikaalisessa käyttöoikeuksien hallinnassa oikeudet riippuvat käyttäjän roolista, esimerkiksi ylläpitäjällä on enemmän oikeuksia kuin tavallisella käyttäjällä. Horisontaalisessa käyttöoikeuksien hallinnassa käyttäjän pitäisi päästä vain omiin tietoihinsa eikä esimerkiksi toisen käyttäjän tilille. Jos käyttöoikeudet on toteutettu huonosti, tavallinen käyttäjä voi esimerkiksi päästä admin sivulle muuttamalla URL osoitetta. Piilotettu admin-sivu voidaan myös yrittää löytää sanalistan ja fuzzing-työkalun avulla.

## Fix the 010-staff-only vulnerability from source code

Korjaus

Haavoittuva rivi tiedostossa staff-only.py oli:
sql = "SELECT password FROM pins WHERE pin='"+pin+"';"
Siinä käyttäjän syöte liitettiin suoraan SQL-kyselyyn.

Korjasin sen parametrisoiduksi kyselyksi:
sql = "SELECT password FROM pins WHERE pin = :pin;"
res = db.session.execute(text(sql), {"pin": pin})
Nyt syöte käsitellään pelkkänä arvona, ei osana SQL-komentoa.

Testaus: Kokeilin ensin oikeaa PIN-koodia 123 → sain "Somedude" (sovellus toimii normaalisti). Sitten kokeilin injektiota ' OR 1=1 LIMIT 2,1 -- → sain "(not found)". Hyökkäys ei siis enää toiminut. Korjaus toimii.

## dirfuzt-1 (ffuf-harjoitus)

VirtualBox-virtuaalikoneessa (Debian/Ubuntu-pohjainen Linux, Firefox). Harjoituskohde dirfuzt-1 ajettiin paikallisesti osoitteessa http://127.0.0.2:8000. Käytin työkalua ffuf.

Tavoite

Harjoitella ffufin käyttöä ja löytää kaksi piilotettua sivua, joihin ei ole linkkiä: admin-sivu ja versionhallintaan liittyvä sivu.

    $ wget https://terokarvinen.com/2023/fuzz-urls-find-hidden-directories/dirfuzt-1
     chmod u+x dirfuzt-1
    ./dirfuzt-1

Ohjelma käynnistyi osoitteessa http://127.0.0.2:8000. Latasin toisessa terminaalissa SecLists-sanalistan (common.txt).

Ajoin ffufin ensin ilman suodatinta:

    $ ffuf -w common.txt -u http://127.0.0.2:8000/FUZZ

Palvelin vastasi lähes kaikkiin osoitteisiin, ja melkein kaikki vastaukset olivat samankokoisia (Size: 154). Ne olivat tyhjiä sivuja.

Suodatin tyhjät vastaukset pois koon perusteella:

    $ ffuf -w common.txt -u http://127.0.0.2:8000/FUZZ -fs 154

Tämän jälkeen jäljelle jäi kaksi löytöä:

/wp-admin (admin-sivu)
/.git (versionhallinnan kansio, mm. .git/HEAD, .git/config, .git/index)

Varmistin löydöt selaimessa, ja molemmista sivuista löytyi teksti "You found it!" ja tehtävän lippu.

## Hack'n Fix – 020-your-eyes-only

Ympäristö

Tein harjoituksen 23.8.2026 omalla koneellani VirtualBox virtuaalikoneessa. Käyttöjärjestelmänä Debian/Ubuntu pohjainen Linux, selaimena Firefox. Harjoitussovellus on Django sovellus, Käytin myös ffuf-työkalua.

Tavoite

Päästä admin konsoliin, jonka sivulla lukee "you've found the secret page". Haavoittuvuus piti löytää web käyttöliittymän kautta.

Mitä tein ja miten etenin

Käynnistin sovelluksen komennoilla:

    $ cd challenges/020-your-eyes-only/
    sudo apt-get -y install virtualenv
    virtualenv virtualenv/ -p python3 --system-site-packages
    source virtualenv/bin/activate
    pip install -r requirements.txt
    cd logtin/
    ./manage.py makemigrations; ./manage.py migrate
    ./manage.py runserver

Sovellus käynnistyi osoitteeseen http://127.0.0.1:8000

Avasin sen selaimessa. Etusivulla oli napit "Show my personal data" ja "Admin dashboard" sekä login ja register painikkeet.

Kokeilin päästä admin sivulle painamalla "admin dashboard" nappia. Se ohjasi kirjautumissivulle (osoite /accounts/login/?next=/admin-dashboard/).

Loin tavallisen käyttäjätilin ("testi") ja kirjauduin sisään. Kokeilin uudestaan mennä /admin-dashboard/-sivulle, mutta sain 403 Forbidden.

Tehtävän vihjeiden mukaan jotkut sivut eivät ole linkitetty mihinkään ja ne voi löytää fuzzerilla. Etsin piilotettuja sivuja ffufilla, samalla tekniikalla kuin dirfuzt1charjoituksessa:

    $ ffuf -w common.txt -u http://127.0.0.1:8000/FUZZ/

ffuf löysi osoitteen /admin-console/

Menin osoitteeseen http://127.0.0.1:8000/admin-console/ kirjautuneena tavallisena "testi" käyttäjänä. Pääsin sisään, ja sivulla luki "Admin secret page Well done, you've found the secret page". Tavoite saavutettu.    


## Hack'n Fix – 020-your-eyes-only korjaus

Tehtävän vihje kertoi, että käyttöoikeudet tarkistetaan tiedostossa views.py, ja että Djangossa tarkistus tehdään usein UserPassesTestMixin-luokan test_func()-metodissa. Etsin tiedoston komennolla:

find ~/challenges/020-your-eyes-only -name views.py

Oikea tiedosto oli logtin/hats/views.py. Avasin sen ja luin sisällön komennolla cat. Tiedostossa oli kolme näkymää, jotka kaikki käyttivät test_func()-metodia käyttöoikeuksien tarkistamiseen.

Vertasin kahta admin-näkymää keskenään. Oikein suojattu näkymä (AdminDashboardView) tarkisti käyttäjän oikeudet näin:

    $def test_func(self):
    return self.request.user.is_authenticated and self.request.user.is_staff

Väärin suojattu näkymä (AdminShowAllView eli /admin-console/) tarkisti vain kirjautumisen:

    $def test_func(self):
    return self.request.user.is_authenticated

Ero oli siis, että väärin suojatusta puuttui tarkistus and self.request.user.is_staff. Ilman sitä sivu päästi kenet tahansa kirjautuneen käyttäjän sisään, myös tavallisen käyttäjän. is_staff on Djangon User-mallin kenttä, joka kertoo onko käyttäjä henkilökuntaa (admin).

Korjasin adminshowallview näkymän lisäämällä siihen saman tarkistuksen kuin oikein suojatussa näkymässä:

    $def test_func(self):
    return self.request.user.is_authenticated and self.request.user.is_staff

Käytin mallina samassa tiedostossa jo ollutta oikein suojattua näkymää. Sain apua sen huomaamisessa, että korjaus on lisätä puuttuva is_staff-tarkistus, mutta ymmärrän miksi se korjaa ongelman: nyt sivulle pääsee vain käyttäjä, joka on sekä kirjautunut että henkilökuntaa.

Testaus

Tallensin muutoksen, ja Django latasi sen automaattisesti uudelleen. Menin osoitteeseen http://127.0.0.1:8000/admin-console/ kirjautuneena tavallisena "testi"-käyttäjänä. Ennen korjausta pääsin sivulle ja näin tekstin "Well done, you've found the secret page". Korjauksen jälkeen sain 403 Forbidden. Korjaus siis esti tavallisen käyttäjän pääsyn admin-sivulle.
