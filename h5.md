# H5 Binääri tässä, missä koodit?

## Lab2

Tehtävässä tarkoituksena oli selvittää käännetyn ohjelman kysymä salasana ja ohjelman tulostama lippu GNU Debuggerin avulla.

Käytin Kali Linuxia VirtualBox-virtuaalikoneessa.

Aloitin purkamalla tehtävän zip-tiedoston:

     unzip lab2.zip

Tämän jälkeen siirryin oikeaan hakemistoon:

     cd lab2/passtr

Tarkistin hakemiston sisällön:

     ls -la

Hakemistossa näkyi muun muassa:

passtr
passtr2o
passtr.c
README.md
Makefile

## 2. Binäärin tarkistaminen

Tarkistin tiedostojen tyypit:

     file passtr passtr2o

Tuloksena passtr oli 64-bittinen ELF-ohjelma:

    ELF 64-bit LSB pie executable, x86-64
    with debug_info, not stripped

Tämä tarkoitti, että binäärissä oli vielä debug-tietoja ja symboleita, joista oli hyötyä GDB:ssä.

## 3. Ohjelman testaaminen

Ajoin ohjelman normaalisti:

     ./passtr

Ohjelma kysyi:

     What's the password?

Testasin väärällä salasanalla:

     kali

Ohjelma vastasi:

     Sorry, no bonus.
    4. GDB:n asentaminen

Kali Linuxissa GDB ei ollut valmiiksi asennettuna, joten asensin sen:

    sudo apt install gdb

Tämän jälkeen avasin ohjelman GDB:llä:

    gdb ./passtr
    5. Funktioiden tutkiminen

GDB:ssä tarkistin ohjelman funktiot:

    info functions

Tuloksessa näkyi esimerkiksi:

    main
    puts@plt
    strcmp@plt
    __isoc99_scanf@plt

strcmp oli kiinnostava, koska sitä käytetään kahden merkkijonon vertailuun.

6. main-funktion tutkiminen

Tutkin main-funktion konekoodia:

    disassemble main

Tuloksessa näkyi kohta:

    0x000000000000119c <+67>: call   0x1040 <strcmp@plt>

Tämän perusteella ohjelma vertasi kahta merkkijonoa kohdassa main+67.

7. Breakpointin asettaminen

Asetin breakpointin juuri ennen strcmp-vertailua:

    break *main+67

GDB vastasi:

    Breakpoint 1 at 0x119c: file passtr.c, line 12.

Tämän jälkeen käynnistin ohjelman:

run

Ohjelma kysyi salasanaa:

    What's the password?

Annoin testiksi:

    kali

Kun ohjelma pysähtyi breakpointiin, GDB näytti suoraan lähdekoodirivin:

    if (0 == strcmp(password, "sala-hakkeri-321")) {

Tästä selvisi, että oikea salasana oli:

    sala-hakkeri-321
    
8. Lipun löytäminen

Ajoin ohjelman uudelleen:

    run

Annoin oikean salasanan:

    sala-hakkeri-321

Ohjelma pysähtyi jälleen breakpointiin. Jatkoin suoritusta komennolla:

    continue

Ohjelma tulosti:

    Yes! That's the password. FLAG{Tero-d75ee66af0a68663f15539ec0f46e3b1}

Lippu oli siis:

FLAG{Tero-d75ee66af0a68663f15539ec0f46e3b1}

## Lab3 – Crackme01 salasanan löytäminen GDB:llä

1. Lab3-tiedoston purkaminen

Siirryin Downloads-kansioon:

    cd ~/Downloads

Tarkistin, että lab3.zip löytyi:

    ls -la

Purin tiedoston:

    unzip lab3.zip

Purkamisessa syntyi kansio:

    lab3/crackmes

Siirryin crackmes-kansioon:

    cd lab3/crackmes

Tarkistin sisällön:

    ls -la

Kansiossa oli useita crackme-tiedostoja, esimerkiksi:

    crackme01.64
    crackme02.64
    crackme03.64
    crackme04.64

Valitsin tutkittavaksi crackme01.64-tiedoston.

2. Binäärin tarkistaminen

Tarkistin tiedoston tyypin:

    file crackme01.64

Tuloksena sain:

    crackme01.64: ELF 64-bit LSB pie executable, x86-64, dynamically linked, not stripped

Tiedosto oli siis 64-bittinen Linux-binääri.

3. Ohjelman testaaminen

Ajoin ohjelman ensin ilman argumenttia:

    ./crackme01.64

Ohjelma vastasi:

    Need exactly one argument.

Tästä selvisi, että ohjelma odottaa yhtä komentoriviargumenttia.

Testasin väärällä salasanalla:

    ./crackme01.64 test

Ohjelma vastasi:

    No, test is not correct.
    
4. Ohjelman avaaminen GDB:llä

Avasin binäärin GDB:llä:

    gdb ./crackme01.64

Tarkistin ohjelman funktiot:

    info functions

Listassa näkyi muun muassa:
    
    strncmp@plt
    puts@plt
    printf@plt
    main

strncmp oli kiinnostava, koska sitä käytetään kahden merkkijonon vertailuun.

5. Main-funktion tutkiminen

Tutkin main-funktion konekoodin:

    disassemble main

Tuloksessa näkyi kohta:

    0x0000000000001168 <+15>: mov    $0x9,%edx
    0x000000000000116d <+20>: lea    0xeab(%rip),%rsi
    0x0000000000001174 <+27>: mov    %rbp,%rdi
    0x0000000000001177 <+30>: call   0x1030 <strncmp@plt>

Tästä näkyi, että ohjelma käyttää strncmp-funktiota merkkijonojen vertailuun.

    mov $0x9,%edx tarkoitti, että vertailussa käytettiin yhdeksää merkkiä.

6. Breakpointin asettaminen

Asetin breakpointin juuri strncmp-kutsun kohdalle:

    break *main+30

GDB vastasi:

    Breakpoint 1 at 0x1177

Käynnistin ohjelman argumentilla test:

    run test

Ohjelma pysähtyi breakpointiin:

    Breakpoint 1, 0x0000555555555177 in main ()
    7. Salasanan tutkiminen muistista

Koska strncmp vertailee kahta merkkijonoa, halusin nähdä toisen vertailtavan merkkijonon.

Käytin komentoa:

    x/s $rsi

Komennossa:

    x tarkoittaa muistin tutkimista
    /s tarkoittaa, että sisältö näytetään merkkijonona
    $rsi tarkoittaa RSI-rekisterin sisältämää muistiosoitetta

GDB näytti:

    0x55555555601f: "password1"

Tästä selvisi, että salasana oli:

    password1
    

8. Salasanan varmistaminen

Poistuin GDB:stä:

    quit

Sen jälkeen testasin salasanaa normaalisti:

    ./crackme01.64 password1

Näin pystyin varmistamaan, että löydetty salasana oli oikea.

## Mitä opin GDB:stä

Tässä tehtävässä opin lisää siitä, miten binääriohjelmaa voidaan tutkia ilman alkuperäistä lähdekoodia.

Opin käyttämään seuraavia komentoja:

     info functions

Näyttää ohjelmasta löytyviä funktioita.
     
     disassemble main

Näyttää main-funktion konekoodin.

     break *main+30

Asettaa breakpointin tiettyyn kohtaan ohjelmaa.

     run test

Käynnistää ohjelman GDB:n sisällä argumentilla.

     x/s $rsi

Näyttää RSI-rekisterin osoittaman muistin merkkijonona.

     Uutta minulle oli erityisesti se, että ohjelman käyttämää salasanaa pystyi tutkimaan suoraan rekisterin kautta ennen strncmp-vertailua.
