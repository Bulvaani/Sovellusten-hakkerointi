# H3 No Strings Attached (Tero)

Aloitin tehtävän lataamalla ezbin-challenges.zip-tiedoston Linuxiin ja purkamalla sen.

Siirryin ensin tehtävän kansioon:

    cd ~/h3/challenges/passtr

Komento cd vaihtaa nykyisen hakemiston annettuun kansioon.

Tarkistin kansion sisällön komennolla:

    ls -la

Komento ls näyttää hakemiston tiedostot. Valinta -l näyttää tiedostojen tarkemmat tiedot, kuten oikeudet ja koon, ja -a näyttää myös piilotetut tiedostot.

Kansiosta löytyivät esimerkiksi seuraavat tiedostot:

    Makefile
    passtr
    passtr.c
    README.md

Tiedosto passtr oli suoritettava binääritiedosto.

Käynnistin ohjelman komennolla:

    ./passtr

Komento suorittaa nykyisessä hakemistossa olevan passtr-ohjelman. ./ tarkoittaa nykyistä hakemistoa.

    Ohjelma kysyi salasanaa:
    
    What's the password?
    
    Kokeilin ensin salasanaa:

    kali

Ohjelma vastasi:

    Sorry, no bonus.

Tämän jälkeen tutkin binääritiedoston sisältämiä tekstimerkkijonoja komennolla:

    strings passtr

strings etsii binääritiedostosta tulostettavia tekstimerkkijonoja. Sen avulla binääristä voidaan löytää esimerkiksi ohjelman tulostamia viestejä, salasanoja ja muita selkokielisiä tekstejä ilman lähdekoodin avaamista.

Tulosteesta löytyivät seuraavat rivit:

    What's the password?
    %19s
    sala-hakkeri-321
    Yes! That's the password. FLAG{Tero-d75ee66af0a68663f15539ec0f46e3b1}
    Sorry, no bonus.

Näiden perusteella ohjelman salasana oli:

    sala-hakkeri-321
    
    ja flag oli:
    
    FLAG{Tero-d75ee66af0a68663f15539ec0f46e3b1}

Tehtävässä opin, että binääritiedostosta voi saada hyödyllistä tietoa jo ennen ohjelman tarkempaa analysointia. strings-komento pystyy näyttämään binäärin sisältämiä selkokielisiä merkkijonoja, minkä vuoksi salasanaa ei kannata tallentaa ohjelmaan suoraan luettavana tekstinä.    

## b) Make a new version of the passtr.c program where the password doesn't appear directly as-is in the binary. Demonstrate with a test that the password doesn't appear. (Obfuscation is sufficient.)

Alotin komennolla 

    cat passtr.c

cat näyttää tiedoston sisällön terminaalissa.

    nano passtr.c

Korvasin tekstin:

    #include <stdio.h>
    #include <string.h>
    
        int main() {
            char password[20];
    
        char correct[] = {
            41, 59, 54, 59, 119, 50, 59, 49,
            49, 63, 40, 51, 119, 105, 104, 107, 0
        };
    
        for (int i = 0; i < 16; i++) {
            correct[i] = correct[i] ^ 90;
        }
    
        printf("What's the password?\n");
        scanf("%19s", password);
    
        if (0 == strcmp(password, correct)) {
            printf("Yes! That's the password. FLAG{Tero-d75ee66af0a68663f15539ec0f46e3b1}\n");
        } else {
            printf("Sorry, no bonus.\n");
        }
    
        return 0;
    }

Tässä salasana on tallennettu char-taulukkoon numeroarvoina. Numeroarvot on XOR-muunnettu avaimella 90, ja ohjelma palauttaa ne takaisin oikeiksi merkeiksi silmukan avulla ennen salasanan vertailua.

Käytin tekoälyä apuna char-taulukon numeroarvojen muodostamisessa sekä XOR-operaation toimintaperiaatteen ymmärtämisessä.

Käänsin ohjelman komennolla:

    gcc passtr.c -o passtr

Tämän jälkeen testasin, löytyykö salasana edelleen binääritiedostosta:

    strings passtr | grep "sala-hakkeri-321"

Komento ei palauttanut mitään tulosta.

Tarkistin vielä koko strings-tulosteen komennolla:

    strings passtr

Tämän perusteella salasana ei enää ole binääritiedostossa suoraan luettavana tekstinä, vaan se on obfuskoitu XOR-operaation avulla.

Mitä opin tehtävistä

Tehtävissä opin binääritiedostojen perusteita ja sitä, miten ohjelmaa voidaan tutkia ilman alkuperäistä lähdekoodia.

A-tehtävässä opin käyttämään strings-komentoa binääritiedoston tutkimiseen. Huomasin, että jos salasana on tallennettu ohjelmaan suoraan selkokielisenä merkkijonona, se voidaan löytää binääristä melko helposti strings-komennolla.

B-tehtävässä opin, että salasanaa voidaan obfuskoida niin, ettei se näy binäärissä suoraan luettavana tekstinä. Käytin XOR-operaatiota ja char-taulukkoa salasanan piilottamiseen. Opin samalla hieman enemmän siitä, miten merkit voidaan esittää numeroarvoina ja miten XOR-operaatiolla muunnetut arvot voidaan palauttaa takaisin alkuperäisiksi merkeiksi ohjelman suorituksen aikana.

C-tehtävässä opin, että binääritiedosto voidaan myös pakata. strings-komennon tulosteesta löytyi viittaus UPX-pakkaukseen, jonka perusteella päätelin ohjelman olevan UPXä pakattu. Opin käyttämään komentoa upx -d packd pakkauksen purkamiseen. Pakkauksen purkamisen jälkeen strings näytti ohjelman merkkijonot selkeämmin ja pystyin löytämään salasanan sekä flagin.

Tehtävien perusteella opin myös, että binäärin analysoinnissa kannattaa edetä vaiheittain. Ensin voidaan tarkistaa tiedoston tyyppi file-komennolla ja etsiä luettavia merkkijonoja strings-komennolla. Jos binääri näyttää olevan pakattu tai muuten suojattu, tulosteesta löytyviä vihjeitä voidaan käyttää seuraavan analyysivaiheen valitsemiseen.
